# T02 — 인플루언서 체험형 데모

목표: 인사담당자가 버튼만 눌러 "발굴 → 점수 → 제안 초안 → 회신 분류 → 보고" 5단계를 1~2분 안에 따라가며, 이 도구가 실제로 어떻게 판단하는지 보게 한다.

먼저 읽을 것: `GEMINI.md`, `GLOSSARY.md`(체험형 데모), `site/data/demo-influencer.json`, `site/assets/css/style.css`(변수·배지·카드 재사용), `site/demos/influencer/index.html`(지금은 자리만 있음)

## 만들 파일 (이 밖은 건드리지 말 것)
- `site/demos/influencer/index.html` — 덮어쓰기
- `site/demos/influencer/demo.js` — 새로
- `site/demos/influencer/demo.css` — 새로 (공통 `style.css` 뒤에 불러옴, 공통 파일은 고치지 않음)

## 화면 구성
- 맨 위 안내 띠: "실제 실행 결과를 가상 데이터로 재생합니다. 이름·연락처는 가상입니다." + 케이스로 돌아가기 링크
- 단계 표시: 1 발굴 · 2 점수 · 3 제안 초안 · 4 회신 분류 · 5 보고 (지금 단계 강조, 누르면 그 단계로 이동)
- 아래쪽 [이전] [다음] 버튼. 5단계에서 [다음] 대신 [처음부터] + [케이스로 돌아가기]
- 각 단계 위에 한 줄 설명(이 단계에서 도구가 무엇을 하는지)

| 단계 | 보여줄 것 (모두 JSON 값으로) |
|---|---|
| 1 발굴 | 해시태그 → 후보 3명 카드: 계정, 이름, 팔로워, 구매 문의 댓글 `buy/total`, 댓글 예시 최대 2개 |
| 2 점수 | 후보별 점수 막대 3개(weights의 max 대비) + 합계 + 판정 배지(적격/탈락) + 사유. 탈락 후보는 흐리게. 막대는 단계에 들어올 때 0에서 차오르게(0.6초, `prefers-reduced-motion`이면 생략) |
| 3 제안 초안 | 메일 미리보기(받는 사람, 제목, 본문 줄들) + DM 문구. 아래 [발송 승인] 버튼 → 누르면 "승인됨 · 발송 완료(데모)" 표시로 바뀜. 승인 전엔 [다음]을 막고 "사람이 승인해야 발송됩니다" 안내 |
| 4 회신 분류 | 회신 2건 카드: 회신 글 + 분류 배지(수락/문의) + 그에 따른 다음 행동(수락 → 출고대기, 문의 → 담당자 답변 필요). 탈락 후보는 "연락하지 않음" |
| 5 보고 | 퍼널 5칸(발굴 3 → 적격 2 → 제안 2 → 회신 2 → 출고 1) 가로 막대, 비율 3개, 안전 규칙 4개 목록 |

## 반드시 지킬 것
- 모든 이름·숫자·문장은 `demo-influencer.json`에서 읽는다. 화면에 새 숫자나 사실을 지어 넣지 않는다 (단계 설명 문장은 JSON의 rules·weights와 어긋나지 않게)
- `fetch("../../data/demo-influencer.json")`로 읽고, 실패하면 "데모 데이터를 불러오지 못했습니다" 안내를 보여준다 (기본값 복사본은 넣지 않는다)
- 이메일 주소는 화면에 보여주지 않는다 (JSON에 있어도 표시 금지)
- 모바일 375px에서 표 대신 카드로, 가로 스크롤 없음. 버튼은 손가락으로 누르기 좋게 최소 44px 높이
- 키보드로도 이동 가능(버튼은 `<button>`), 단계 표시는 `aria-current="step"`
- 한국어만, 외부 라이브러리 없음

## 완료 조건
1. 처음 → 5단계 → 처음부터까지 막힘 없이 동작, 3단계 승인 전에는 [다음]이 막힘
2. 화면의 모든 값이 JSON과 일치, 이메일 비노출
3. 375·768·1280px에서 가로 스크롤 없음
4. 콘솔 오류 없음 (코드상 예상 오류가 없도록)
