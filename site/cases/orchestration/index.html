기록 케이스 05

오케스트레이션

Claude 지휘와 Gemini 제작으로 이 포트폴리오 웹사이트를 구축한 AI 협업 방식

01 문제

AI에게 일을 시키면 빠르지만, 그대로 믿으면 틀린 숫자와 깨진 화면이 그대로 나간다

제작 AI가 스스로 '모든 기준 통과'라고 보고하더라도, 실제로는 자료에 없는 인과나 확인되지 않은 숫자, 모바일 환경에서의 가로 넘침 같은 결함이 검증 없이 남아있을 수 있습니다.

02 판단

역할을 나눈다

오너, 지휘자, 제작자의 역할을 나눠, 만드는 쪽과 확인하는 쪽이 같지 않게 합니다.

나 (오너)

무엇을 만들지, 무엇을 공개할지 정한다. 질문에 답하고 스펙을 승인한다

Claude (지휘)

질문으로 기획을 정리하고, 지시서를 쓰고, 결과를 직접 띄워 검수한다. 한두 줄은 직접 고친다

Gemini (제작)

지시서 한 장 단위로 파일을 만들고 보고서를 쓴다. 파일 편집 권한만 있다

핵심 원칙: 만든 AI가 스스로 '통과'라고 해도, 지휘자가 직접 띄워 재고 근거와 대조한다
03 AI에게 시킨 것

기획 정리부터 검수·수정까지 4단계 협업 흐름

오너 인터뷰를 통한 기획 정리부터 지시서 작성, 제작, 검수, 마일스톤 보고까지 4단계 파이프라인으로 진행합니다.

1단계

질문으로 기획 정리 (5라운드, 30여 개 결정)

2단계

스펙·용어집·결정 기록 승인

3단계

지시서 → 제작 → 검수 → 수정 지시

4단계

마일스톤마다 보고

04 결과

M1 마일스톤 성과 지표 및 검수·수정 실사례

작업 3개를 거치며 지휘자가 직접 브라우저로 띄워 검수하고 수정 지시를 전달했습니다. 실패와 수정 사실을 감추지 않고 협업 기록으로 보존합니다.

T01 사이트 뼈대 근거 없는 문장 9건을 잡아냈다
▾
무슨 일이 있었나

제작 보고서는 '모든 수치와 문장은 근거와 일치 ✅'였지만, 검수에서 자료에 없는 인과("공구 36억이 성장을 견인"), 확인시킬 수 없는 숫자("검증된 도구 6종"), 지어낸 설명 문단 등 9건이 나왔다

어떻게 지시했나

문장마다 '지금 → 이렇게'를 표로 적은 수정 지시서를 다시 보냈다

결과

2번째 결과에서 통과. 이후 모든 지시서에 '숫자·사실은 데이터 파일에서만 읽는다'를 넣었다

T02 체험형 데모 '가로 스크롤 없음 ✅'을 직접 재서 뒤집었다
▾
무슨 일이 있었나

보고서는 반응형 통과였지만, 휴대폰 폭(375px)으로 띄워 재 보니 1·2단계 화면 폭이 529px로 넘쳤다. 원인은 후보 카드 3개가 한 줄에 고정된 것

어떻게 지시했나

넘치는 요소와 수치, 고칠 방법(640px 이하 한 줄에 1개), 확인 방법까지 적어 수정 지시

결과

375·768·1280px 모든 단계에서 넘침 0으로 통과

T02a 데모 데이터 (Claude 직접) 공개하면 안 되는 샘플 데이터를 먼저 걸렀다
▾
무슨 일이 있었나

원 프로젝트의 '샘플' 데이터에 실제 도메인 이메일, 전화번호, 실존 건물 주소, 실존 경쟁 브랜드명이 들어 있었다

어떻게 지시했나

제작자에게 원본을 넘기지 않고, 구조만 남긴 가상 데이터 파일을 지휘자가 직접 만들어 넘겼다

결과

데모 화면에는 가상 값만 나오고, 이메일은 표시하지 않는다

작업 시작 직후 제작 도구가 막혀도 멈추지 않았다
▾
무슨 일이 있었나

Gemini CLI가 개인 무료 계정 지원 종료로 로그인 실패. 다음엔 제작자가 폴더를 만들려고 명령을 실행하다 권한에 막혀 멈췄다

어떻게 지시했나

같은 계정의 Antigravity CLI로 바꾸고(Gemini 3.8 Flash, 파일 편집만 허용), 폴더는 지휘자가 미리 만들고 '명령 없이 파일만 쓰라'고 지시를 고쳤다

결과

권한을 넓히지 않고 해결. 바꾼 이유는 결정 기록으로 남겼다
